1. Scope

This report covers the implemented features corresponding to the project build order through borrowing history:

  • Member management — register, list, suspend, reactivate (librarian)
  • Authentication — form login by email, BCrypt passwords, role-based access
  • Circulation — borrow and return with transactional availability updates
  • Waitlist — join, leave, READY promotion, hold expiry
  • Borrowing history — account page with open loans, waitlists, and ledger

Architecture rule: controllers call services; services call repositories; no controller→repository shortcuts. Multi-step writes (borrow, return) are @Transactional.

4. Member registration sequence

Librarians issue cards at POST /admin/members. New accounts always receive Role.MEMBER and MemberStatus.ACTIVE; the password is stored only as a BCrypt hash.

sequenceDiagram
    actor Librarian
    participant MC as MemberController
    participant MS as MemberService
    participant PE as PasswordEncoder
    participant MR as MemberRepository
    participant DB as Database

    Librarian->>MC: POST /admin/members
    MC->>MC: validate MemberForm
    alt validation fails
        MC-->>Librarian: redisplay form
    else valid
        MC->>MS: register(form)
        MS->>MS: normalize email
        MS->>MR: existsByEmail(email)
        MR->>DB: SELECT
        alt duplicate email
            MS-->>MC: DuplicateEmailException
            MC-->>Librarian: field error
        else new email
            MS->>PE: encode(password)
            PE-->>MS: BCrypt hash
            MS->>MS: role MEMBER, status ACTIVE
            MS->>MR: save(member)
            MR->>DB: INSERT
            MS-->>MC: Member
            MC-->>Librarian: redirect + notice
        end
    end

6. Login sequence

Email is the username. LibraryUserDetailsService loads the member; Spring Security verifies the BCrypt hash. POST /login is handled by the security filter, not a controller method.

sequenceDiagram
    actor User
    participant Browser
    participant SC as SecurityFilterChain
    participant UDS as LibraryUserDetailsService
    participant MR as MemberRepository
    participant PE as PasswordEncoder

    User->>Browser: GET /login
    Browser-->>User: login form
    User->>SC: POST /login (email, password)
    SC->>UDS: loadUserByUsername(email)
    UDS->>UDS: lowercase email
    UDS->>MR: findByEmail(email)
    alt not found
        UDS-->>SC: UsernameNotFoundException
        SC-->>User: /login?error
    else found
        UDS-->>SC: UserDetails + ROLE_*
        SC->>PE: matches(raw, hash)
        alt bad password
            SC-->>User: /login?error
        else ok
            SC->>SC: create session
            SC-->>User: redirect /catalog
        end
    end

8. Borrow sequence

Borrow decrements availableCopies and inserts a Loan with due date = today + 14 days in one transaction. A member with a READY hold collects that reserved copy instead of competing with walk-ins.

sequenceDiagram
    actor Member
    participant CC as CirculationController
    participant MS as MemberService
    participant LS as LoanService
    participant WS as WaitlistService
    participant BR as BookRepository
    participant LR as LoanRepository

    Member->>CC: POST /books/{id}/borrow
    CC->>MS: getByEmail(principal)
    CC->>LS: borrow(bookId, member)
    LS->>BR: findById(bookId)
    alt suspended
        LS-->>CC: BorrowNotAllowedException
    else active
        LS->>WS: expireStaleHolds(book)
        LS->>WS: readyHold(book, member)
        alt has READY hold
            LS->>LS: mark hold FULFILLED
        else no hold
            LS->>WS: effectiveAvailable(book)
            alt no free copy
                LS-->>CC: BorrowNotAllowedException
            end
        end
        LS->>LS: availableCopies -= 1
        LS->>LS: dueDate = today + 14
        LS->>LR: save(loan)
        LS-->>CC: Loan
        CC-->>Member: redirect /account
    end

9. Return sequence (with waitlist promotion)

Return closes the loan, increments availability, and promotes the front of the ACTIVE waitlist to READY in the same transaction.

sequenceDiagram
    actor Member
    participant CC as CirculationController
    participant LS as LoanService
    participant WS as WaitlistService
    participant WR as WaitlistRepository

    Member->>CC: POST /loans/{id}/return
    CC->>LS: returnLoan(loanId, member)
    alt not owner or already returned
        LS-->>CC: error
    else open loan
        LS->>LS: returnDate = today
        LS->>LS: availableCopies += 1
        LS->>WS: promoteNext(book)
        WS->>WR: first ACTIVE by joinedAt
        alt someone waiting
            WS->>WS: status READY, readyAt now
        else empty queue
            Note over WS: copy stays free
        end
        LS-->>CC: Loan
        CC-->>Member: redirect /account
    end

10. Join / leave waitlist

Join is allowed only when no copy is effectively available, and only once per member per title (ACTIVE or READY).

sequenceDiagram
    actor Member
    participant CC as CirculationController
    participant WS as WaitlistService

    Member->>CC: POST /books/{id}/waitlist
    CC->>WS: join(bookId, member)
    WS->>WS: expireStaleHolds(book)
    alt suspended or already waiting or copies available
        WS-->>CC: WaitlistException
    else allowed
        WS->>WS: create ACTIVE entry
        WS-->>CC: WaitlistEntry
        CC-->>Member: notice with position
    end

    Member->>CC: POST /waitlist/{id}/cancel
    CC->>WS: cancel(entryId, member)
    alt was READY
        WS->>WS: CANCELLED then promoteNext
    else was ACTIVE
        WS->>WS: CANCELLED
    end
    CC-->>Member: redirect /account

11. Waitlist state machine

READY holds last 3 days (CirculationPolicy.HOLD_PERIOD_DAYS). Expiry is checked lazily at borrow/join time.

stateDiagram-v2
    [*] --> ACTIVE: join waitlist
    ACTIVE --> READY: return promotes front of line
    READY --> FULFILLED: holder borrows
    READY --> CANCELLED: leave list OR hold expires
    ACTIVE --> CANCELLED: leave list
    FULFILLED --> [*]
    CANCELLED --> [*]

12. Account / borrowing history

GET /account loads the signed-in member’s card, open loans (with return actions), waitlist standings, and full loan ledger.

sequenceDiagram
    actor Member
    participant AC as AccountController
    participant MS as MemberService
    participant LS as LoanService
    participant WS as WaitlistService

    Member->>AC: GET /account
    AC->>MS: getByEmail(principal)
    AC->>LS: historyFor(member)
    Note over LS: all loans newest first
    AC->>WS: standingsFor(member)
    Note over WS: ACTIVE + READY with position
    AC-->>Member: account view
